# Flight Commander 4.3.2

Flight Commander 4.3.2 is a coordinated Configurator and Firmware release for
all 50 official STM32H743 and STM32H757 targets. Every firmware image and the
Configurator report the exact 4.3.2 version.

## Bidirectional DShot

Firmware 4.3.2 adds opt-in bidirectional DShot eRPM telemetry for DShot150,
DShot300, and DShot600. Extended DShot Telemetry (EDT) decoding for ESC
temperature, voltage, and current is available as a separate opt-in setting.
Both settings are off by default, so upgrading does not change existing motor
output behavior.

The Configurator adds the two settings to Outputs and reports per-motor
telemetry freshness and mechanical RPM. DSHOT150 is now handled consistently
with DSHOT300 and DSHOT600 by the digital-output controls. The PID Tuning help
also directs operators to verify every motor's RPM source before enabling the
RPM gyro filter.

### Enable it safely

1. Remove every propeller and restrain the aircraft.
2. On Outputs, select DSHOT150, DSHOT300, or DSHOT600.
3. Set the correct number of magnetic motor poles.
4. Enable **Bidirectional DShot**. Enable **Extended DShot Telemetry** only
   when the installed ESC firmware explicitly supports EDT.
5. Save and reboot. These settings are initialized only during boot.
6. Reconnect and verify fresh telemetry for every motor. Run only a restrained,
   propeller-off motor test and confirm that RPM rises and falls plausibly.
7. Enable RPM filtering only after all required motor RPM sources remain fresh.

Enabling bidirectional DShot makes it the ESC telemetry source and takes
precedence over a configured serial ESC telemetry UART. If telemetry becomes
stale, its per-motor RPM notch is removed instead of being held at the minimum
frequency. Stale ESC values are invalidated rather than remaining visible.

### Hardware and output boundary

All 50 official images contain the implementation. Static target validation
confirms that the first four motor outputs on every official target use normal
timer channels with distinct per-channel DMA selections. Bidirectional DShot
fails closed during output initialization when a selected motor mapping uses a
complementary timer output or lacks a dedicated DMA channel; it never silently
falls back to unidirectional DShot while the setting remains enabled.

Some high-output-count target mappings have later outputs that cannot support
the required per-channel receive DMA. Known examples include output 12 on
`AXISFLYINGH743PRO`, outputs 8 and 10 on `DAKEFPVH743`, output 12 on
`DAKEFPVH743PRO`, output 12 on `DAKEFPVH743_SLIM`, and outputs 8 and 10 on
`HAKRCH743`. Cube Orange+ AUX6 also shares a DMA selection with AUX1; use the
first four unique AUX outputs for a four-motor bidirectional DShot setup.

Compilation and static verification are not a substitute for propeller-off
validation on the exact controller, ESC firmware, motor mapping, protocol
rate, and electrical installation. Treat EDT as experimental until its values
have been compared with independent voltage, current, and temperature
measurements.

## Firmware hardening

The H7 implementation switches shared timers between the DShot output period
and a wide input-capture period, protects the line while timer channels are
reconfigured, and uses separately aligned DMA buffers with explicit data-cache
maintenance. Telemetry parsing rejects malformed pulse lengths and tracks
fresh eRPM independently for each motor.

Bidirectional DShot settings live in a new parameter group. Updating from
4.3.1 therefore preserves the existing motor protocol, output rate, digital
idle, and motor-pole settings instead of resetting the complete motor group.
EDT values are converted to Flight Commander's centivolt and centiamp units.

The implementation is derived from the GPLv3 work in INAV pull request 11605
and the corresponding Betaflight H7 direction-switching design, with additional
H7 cache, migration, freshness, output-validation, and release safeguards for
Flight Commander's target set.

## Coordinated 50-target publication

The previous two-target release plus additive H7 publisher has been replaced
by one canonical pipeline driven by `flight-commander/official-targets.txt`.
The official release publishes:

- 50 standalone long-name firmware HEX files for the online flasher;
- one `Flight-Commander-v4.3.2.zip` complete bundle containing the Windows
  Configurator, Configurator source, firmware source, and all 50 short-name HEX
  files (53 bundle entries total).

Before publication, each firmware artifact is checked for its target string,
embedded `FCFW` 4.3.2 identity, target-aware capability mask, Intel HEX
integrity, bootloader-safe address range, source identity, filename, size, and
SHA-256 digest. The release is staged as a draft, all 51 uploaded assets are
verified, and only then is it made public.

## Validation boundary

The release gate compiles all 50 targets with Arm GNU Toolchain 13.2.1 and
warnings as errors, runs the Configurator and release-contract test suites, and
verifies every generated artifact. Hardware acceptance still requires a
propeller-off bench run on representative H743 and H757 controllers, including
DShot150/300/600, telemetry loss, RPM-filter tracking, EDT units, CPU load, and
signal turnaround on the outputs actually used.
