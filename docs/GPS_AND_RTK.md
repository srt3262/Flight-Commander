# GPS and RTK

Flight Commander supports a normal serial u-blox receiver, an explicit UART
F9-series RTK rover, supported DroneCAN GPS/RTK nodes, and dual-receiver
moving-baseline heading when the connected firmware advertises each capability.

## Terms

- **Rover** is the receiver on the aircraft. It calculates its position and
  accepts RTCM correction messages.
- **Base** is a stationary receiver whose known/surveyed position is used to
  generate RTCM corrections.
- **RTK Float** means ambiguity resolution is incomplete.
- **RTK Fixed** is the high-confidence resolved state. It can still be wrong if
  the base position, antenna geometry, or correction stream is wrong.
- **Moving baseline** uses two aircraft GNSS antennas for relative heading. It
  is different from using one rover plus a stationary ground base.

## UART F9 RTK rover

Use this for a u-blox ZED-F9P or compatible F9-series aircraft receiver wired
to a flight-controller UART.

1. In **Ports**, assign the receiver UART the normal **GPS** function and set
   `115200` baud unless the hardware is deliberately configured otherwise.
2. Save/reboot and return to **GPS**.
3. Under **Serial-based receiver (UART)** choose
   **u-blox F9P / F9-series (RTK Rover)**.
4. The preset selects u-blox protocol, `115200` baud, GPS/Galileo/BeiDou/GLONASS,
   and an 8 Hz navigation update rate.
5. Save/reboot, then verify satellite, fix, age-of-correction, and RTK state
   telemetry before flight.
6. In Ground Control choose direct NTRIP, local survey-in base, or
   NTRIP-refined base corrections.

The preset is explicitly selected. Existing firmware statistics identify M8,
M9, and M10 generations but do not provide a reliable F9 hardware identifier,
so Flight Commander does not pretend to auto-detect F9 from that field.

An F9 board can also include an external magnetometer. That compass is a
separate sensor: enable it as a heading source, calibrate it in **Calibration**,
and set its installation rotation in **Alignment Tool**. The GNSS receiver does
not become a compass merely because it supports RTK.

## DroneCAN GPS and RTK

DroneCAN setup requires firmware support and a correctly wired/terminated CAN
bus.

1. Set the CAN bitrate and enable the bus in **Ports**.
2. Open **GPS**, enable DroneCAN GPS, and discover nodes.
3. Select automatic node binding or a specific node ID as appropriate.
4. Confirm the detected node provides the expected GNSS/RTK service.
5. Save/reboot and verify that the same node returns after power cycling.

If the module also publishes a compass, treat its node-bound compass as a
separate calibration/alignment target. Do not transfer calibration coefficients
between node IDs.


### Two-node Holybro/AP_Periph moving-baseline pair

With Flight Commander Firmware 4.0.0, select the two discovered GNSS nodes as **Moving Base** and **Moving Rover**. The one-stage setup manager assigns AP_Periph moving-baseline roles, saves and restarts both modules, and verifies role readback. Select the rover as navigation primary when practical, but keep navigation selection logically separate from the fixed base/rover heading roles.

Leave module termination unchanged unless the physical CAN topology is known. Exactly the two ends of the CAN trunk should be terminated; a hub or another peripheral may already provide one or both terminations.

## Concurrent receivers and primary navigation

When firmware advertises concurrent UART and DroneCAN GPS support, both
receivers can remain active and report independent fix/RTK states. Select one
navigation primary; the other remains observable and can receive corrections.

Choose the primary based on antenna placement, view of sky, update quality,
noise, and failure behavior—not simply which receiver first reports a fix.

## Correction paths

Ground Control offers three guided paths:

| Workflow | Correction source | Aircraft receives |
| --- | --- | --- |
| Direct NTRIP to aircraft | Internet caster | Caster RTCM forwarded directly to enabled aircraft correction paths |
| Survey-in USB base | Local stationary F9 base | RTCM generated by the surveyed local base |
| NTRIP-refined USB base | Caster plus local F9 base | A guarded RTK-Fixed position refines the base, then the local fixed base generates RTCM |

See [USB RTK base and NTRIP](RTK_BASE_NTRIP.md) for receiver setup, credentials,
survey quality, stream validation, and safe switchover rules.

## Alignment targets

Alignment Tool lists supported RTK-related targets independently:

- **UART RTK GPS-module compass** — roll/pitch/yaw installation angles for the
  physical compass carried by the UART module.
- **DroneCAN RTK GPS-module compass** — node-specific compass installation
  angles.
- **Dual RTK moving-baseline pair** — yaw installation offset between the
  measured baseline direction and aircraft forward.

The 3D F9, DroneCAN, and antenna-pair views are connection-aware schematics:
they distinguish UART from external I²C compass wiring, CAN connectors, and the
Base→Rover baseline vector. Always confirm the module manufacturer's axis marks
and the actual installation before saving an alignment.

The GPS tab contains source selection, priority, weight, and validity controls,
but no orientation correction fields. All mounting alignment is owned by
Alignment Tool so a second hidden yaw correction cannot be applied.

## Moving-baseline GNSS yaw

Moving-baseline heading requires two GNSS receivers/antennas, a known baseline
direction and length, valid relative-position data, and firmware capability.
Flight Commander rejects stale, non-fixed, geometrically implausible, or
inaccurate relative-heading data before fusion. Configure the baseline yaw
offset in Alignment Tool and monitor its health in the heading diagnostics.

See [Heading fusion](HEADING_FUSION.md) for priorities, weights, calibration,
failover, and disagreement rejection.

## Preflight RTK checks

- Confirm the expected primary receiver and both receiver identities.
- Confirm a 3D fix before interpreting RTK state.
- Verify correction age remains current and the RTCM byte/message counters move.
- Confirm the local base is stationary and its stored position is intended.
- Wait for RTK Fixed when the operation requires it; do not treat Float as Fixed.
- Verify each enabled heading source is healthy and calibrated.
- Check that loss of NTRIP/base data produces the intended degraded-navigation
  behavior without destabilizing heading or flight modes.

## Troubleshooting

- No F9 choice: install Configurator 2.0.5 or newer and select the explicit
  F9-series RTK rover preset.
- No RTK alignment target: verify Flight Commander firmware identity and the
  UART RTK, DroneCAN, heading-fusion, or moving-baseline capability card.
- GPS absent after reboot: recheck the Ports function, baud, RX/TX crossover,
  voltage level, and module power.
- Corrections count but no Float/Fixed: verify RTCM compatibility, base distance,
  common constellations, antenna view, and correction age.
- Compass calibration succeeds but values do not change: reopen Calibration and
  confirm the correct physical source card/node; see
  [Troubleshooting](TROUBLESHOOTING.md).
