    Waiting for DroneCAN bus status…

    UART and DroneCAN receivers remain active together. Either can be the navigation primary, and both retain independent RTK Float/Fixed state and receive RTCM corrections. Battery-node assignments remain available in Ports.

    Flight Commander heading sources

    Priority 1 is the primary authority and disagreement anchor. All healthy enabled sources inside the disagreement limit contribute according to weight; invalid or stale sources are removed automatically and the next priority becomes primary. Enabled sources must use unique priorities, and each enabled magnetic compass must be calibrated before it contributes.

    Fused heading: Waiting for data…

    UART GPS-module compass

    The GPS UART carries GNSS data; its compass uses the module cable's SDA/SCL wires on the flight controller's external I²C1 connector. Enabling or changing this source requires Save and Reboot, followed by compass calibration.

    DroneCAN compass mounting

    DroneCAN MagneticFieldStrength2 is body-frame data. Use these values only when the module's published mounting orientation is not aligned with the aircraft. Flight Commander applies its own per-node hard-iron offset and per-axis gain calibration before this mounting rotation.

    Moving-baseline yaw

    Both GNSS units must be configured as a real moving-base pair and the rover must emit a relative-heading solution. Flight Commander does not infer yaw from two ordinary latitude/longitude fixes.
