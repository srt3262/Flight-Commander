ArduPilot controller mission-interruption behavior

Connect to an ArduPilot controller over MAVLink to read this setting.

This is ArduPilot's persistent MIS_RESTART parameter. Flight Commander's exact resume command requires RESUME (0) and re-reads the controller value before selecting the saved mission item.

INAV controller mission-interruption behavior

Connect through the wired INAV/MSP setup link to read this controller setting.

This is INAV's persistent nav_wp_mission_restart firmware setting. Native RESUME continues from the last active waypoint when NAV WP is reselected, but only while the flight controller remains powered and the aircraft remains armed; disarming resets INAV's native active waypoint to the mission start. SWITCH permits that native resume once, then restarts from the first waypoint on the next NAV WP selection. This is separate from Flight Commander's estimated in-memory MAVLink checkpoint, which can write a remaining active-RAM mission suffix after disarm during the same powered session without changing the persistent MSP mission.

Flight Commander telemetry checkpoint: No mission checkpoint has been captured for this vehicle.
A resume checkpoint records mission progress observed over MAVLink so a mission can continue after an RTH/RTL interruption and battery swap while the flight controller remains powered. This covers an RC-selected RTH even though MAVLink does not identify which source selected the mode. ArduPilot progress is exact; INAV progress is position-estimated and resumed by a verified active-RAM suffix. It does not configure radio, battery, or telemetry link-loss failsafes.
